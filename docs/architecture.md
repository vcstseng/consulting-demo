# 整合方向草稿

## 使用目的

讓一般人理解：從企業問題出發，可以參考哪些外部做法、需要哪些能力，並在未來的方案示範中看到 Consulting Agents 的分析方式。目前先建立網站殼，不要求先走通一個案例。

## 閱讀路徑

1. 首頁介紹整體概念與三塊之間的關係。
2. 進入企業領域，在同一頁探索企業問題、外部做法參考與能力。
3. 深入各類詳情，再回到原領域；保留語言與閱讀脈絡。
4. 方案示範先保留清楚的待補位置，案例內容與 matching 後續再決定。

三個模組仍可獨立探索。整合版共用網站導覽與閱讀脈絡，不要求把三個原網站版型完全相同。哪些既有資料先接入、採何種框架，尚未決定。

## 資料邊界

先記錄來源位置與版本，再按授權建立必要的展示資料。穩定 ID 用於引用；不急著建立共用資料庫或 matching 引擎。同分類不等於已匹配，不虛構新創、repo 功能或案例成果。

99 Problems 與 Capability Store 的企業分類對齊；Startup Radar 維持外部參考角色，領域對應仍需確認。能力層的人工判斷與權限沿用說明，方案層的治理在未來示範中交代。
